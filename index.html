Engineering case studies

Selected work from regulated financial-services products. Details are anonymized to protect confidential systems and customer information.

  • Case study 1

    Improving developer velocity with AI-ready architecture

    Lead Frontend Engineer & Architecture Owner

    Challenge
    A growing Next.js application had blurred domain boundaries and inconsistent conventions, slowing onboarding and causing AI coding tools to apply outdated patterns.
    Approach
    Created localized documentation across application domains, established repository-wide Copilot guidance, and configured a Playwright MCP workflow so AI agents could inspect and validate browser behavior in local development.
    Accessibility & performance
    Built WCAG 2.1 AA expectations and performance budgets into the shared engineering guidance so generated implementations favor semantic HTML and lean client components.
    Outcome
    Made project conventions easier for new contributors and AI-assisted workflows to discover, reducing review churn and improving first-pass test alignment.
    • Next.js App Router
    • Drizzle ORM
    • Playwright
    • MCP
    • GitHub Copilot

  • Case study 2

    Simplifying loan-offer selection across devices

    Frontend Lead

    Challenge
    A multi-step partner-funnel flow created cognitive friction, and offer states could be ambiguous when no option was preselected or rates varied.
    Approach
    Delivered a responsive single-screen offer experience with featured and selectable cards, fallback logic for unselected offers, and viewport-aware ordering for desktop and mobile layouts.
    Accessibility & performance
    Implemented keyboard-operable selection with explicit selected and checked states. CSS Grid transitions limited layout shift while memoized sorting avoided unnecessary rerenders.
    Outcome
    Removed empty-state failures and created a faster, clearer offer-selection interaction for a high-traffic financial-services funnel.
    • React
    • TypeScript
    • Responsive UI
    • ARIA
    • Performance Optimization

  • Case study 3

    Raising the accessibility baseline across a web application

    Accessibility Champion & Core Frontend Developer

    Challenge
    Accessibility audits identified missing bypass navigation, incomplete asynchronous validation announcements, inconsistent focus behavior, and motion triggers across shared experiences.
    Approach
    Introduced a global skip link, semantic form-error associations and live regions, standardized keyboard support and visible focus states, and added reduced-motion safeguards.
    Accessibility & performance
    Validated patterns against WCAG 2.1 AA expectations and screen-reader behavior while preserving approved visual design and existing analytics.
    Outcome
    Resolved compliance risks across primary customer journeys and translated accessibility requirements into repeatable PR criteria and automated test coverage.
    • React
    • WAI-ARIA
    • WCAG 2.1 AA
    • Screen Readers
    • Automated Testing

  • Case study 4

    Making regulatory disclosures self-service and secure

    Full-Stack Frontend Architect

    Challenge
    Legal and marketing teams needed to update disclosures quickly without raw CMS HTML, inconsistent design, or avoidable security and accessibility risk.
    Approach
    Connected CMS rich-text links to version-controlled dialog components, allowing editors to select approved disclosures while the application safely rendered the matching modal.
    Accessibility & performance
    Implemented labeled dialogs with focus trapping, Escape-key support, and focus return. Dialog content was loaded on interaction to keep initial payloads lean.
    Outcome
    Enabled stakeholders to place approved disclosures independently while preserving consistent presentation, accessible interactions, and controlled content delivery.
    • React
    • Headless CMS
    • Accessible Dialogs
    • Dynamic Imports
    • Content Security
